# Security Policy

Quard is security-sensitive software. Please do **not** disclose vulnerabilities, exploit payloads, production configuration or sensitive logs in a public issue or pull request.

## Supported versions

**No public stable Quard 2.0 release is currently supported.** Development and engineering-candidate versions are not guaranteed suitable for production.

## Reporting vulnerabilities

The maintainers are setting up a verified private reporting channel. Until it is confirmed, **do not assume that GitHub Private Vulnerability Reporting is enabled**.

If the repository's **Security and quality → Report a vulnerability** action is available, use GitHub's private vulnerability-reporting workflow. Otherwise, open a public issue *without technical vulnerability details* asking the maintainers for a private reporting channel. Do not post the proof of concept, sensitive URLs, or payloads there.

A report should privately include the affected revision, impact, reproduction steps, and a minimal sanitized proof of concept.

## Maintainer action required

Before publishing a stable release, repository administrators must enable GitHub Private Vulnerability Reporting, verify the submission interface and recipient notifications, and then update this document to state the confirmed route. A file alone does not turn on that GitHub feature.
